# gimbal(云台yaw)

## 硬件

- 单块C板,云台只有一个yaw轴:大疆GM6020(直驱,没有减速箱),挂在**CAN1**上,拨码ID = `YAW_MOTOR_ID`(实测拨码=3)。
  - 控制报文:0x1FE(ID 1~4);反馈报文:0x207(0x204 + ID)。
- C板自带BMI088,但目前云台yaw速度环仍只使用6020自己的编码器;BMI088的航向控制用于底盘。

## 云台一共两种状态

| 模式 | 名字 | 一句话说明 |
| --- | --- | --- |
| 0 | `YAW_ZERO_FORCE` | 急停:不给电流,云台可以被手随便转 |
| 1 | `YAW_SPEED_CTRL` | 速度闭环:告诉它"每秒转多少度",它就一直转。**定速旋转、变速转动**两个档用它,区别只在目标速度怎么来(固定值 / 加速度积分) |

用哪个模式由 `robot_cmd` 根据拨杆决定,通过 `gimbal_cmd` 话题发过来,`gimbal` 只管照着做。

## 重点:定速旋转是怎么做的

### 一句话

给速度环一个**目标角速度**(比如 360°/s),让它自己去把转速做出来。
唯一多做的一件事是**给这个设定值加变化率限幅**(`YAW_SPEED_SLEW`),让它从当前值慢慢爬到目标值,
而不是一步跳过去 —— 这就是"起步不冲、不来回摆"的关键。

### 详细一点

假设定速档给的是 360°/s,限幅是 1200°/s²,云台任务每 1ms 执行一次,于是设定值是这样爬上去的:

| 时刻 | 速度环的设定值 | 说明 |
| --- | --- | --- |
| 进档那一拍 | 1.2°/s | 从0开始,每拍最多加 1200×0.001 = 1.2°/s |
| 0.15s | ≈180°/s | 电机一直跟在设定值后面一点点,误差很小 |
| 0.3s | 360°/s | 到达目标值,之后一直保持 |
| 稳态 | 360°/s | 摩擦造成的转速静差由速度环的**积分 Ki** 补掉 |

### 为什么不用以前那套"角度斜坡 + 角度环 + 速度前馈"

那套做法是"让目标角度每拍往前走 0.36°,再让角度环去追",实测有两个毛病:

1. **起步会超驱动**:进档那一拍参考角度立刻以 360°/s 往前跑,而电机还在从 0 加速,几十毫秒里
   角度误差就涨到十几度 → 角度环输出撞上限幅 → 速度环设定被顶到 720°/s → 电机冲过头再拉回来。
   这跟 Kp/Ki 取多少关系不大,是结构问题。
2. **会把机械扰动放大成共振**:角度环的带宽 ≈ Kp = 12 rad/s ≈ 1.9Hz,而云台机械上有一圈一次的
   阻力脉动(360°/s 时正好 1Hz),两者撞在一起,就变成"1 秒一个来回"的大振荡。

改成现在这样(限幅 + 速度环积分)之后,角度环整个撤掉了(原来用它的锁角度档,先改成"停云台",现在干脆改成"没有命令就卸电"),上面两个问题也都不存在了。
另外那条 1Hz 的机械脉动依然在(它来自机械,不是控制器)——要在机械上解决:配重、理线、查轴承。

### 对应到代码(都在 `gimbal.c` 的 `GimbalTask()` 里)

| 代码 | 干的活 |
| --- | --- |
| `yaw_speed_ref += YAW_SPEED_SLEW * dt;` | 变化率限幅:设定值每拍最多变 0.6°/s,爬到目标值为止 |
| `DJIMotorSetRef(gimbal_yaw_motor, yaw_speed_ref);` | 把限幅后的设定值交给速度环 |
| 速度环的 `Ki` | 消掉摩擦造成的转速静差(定速档不再靠角度环了) |

> 另外 `GimbalTask()` 开头给 `dt` 做了兜底:超过50ms就按1ms算。
> 原因是任务刚起来(或被调试器停住再放开)的那一拍,`dt` 可能是几百毫秒,
> 而"变化率限幅"是 `YAW_SPEED_SLEW × dt` —— dt一大,限幅就一步跨到目标值,等于没限幅,起步照样冲。

> 目标角速度的单位是**°/s**,和模块层速度环的反馈单位`measure.speed_aps`一致。
> 所以`YAW_SPEED_KP`的含义是"每1°/s的误差输出多少个电流指令":KP=10 表示 100°/s 的误差对应 1000 的电流指令。

## 变速档前馈:两个"提前算出来的电流"(物理补偿用)

速度环必须"先有误差才出力",所以它天生会把反馈里的抖动放大(电调报的转速估计 + 机械上一圈一次的脉动),
表现出来就是电流和声音发毛。前馈的作用是**把能提前算出来的那部分电流自己先喂进去**,让速度环只去管剩下的扰动,
于是你就敢把 Kp 调低 ——而 P 放大抖动正是噪声的第一来源。两个前馈都加在**电流指令**上,增益默认 0 = 不启用。

| 前馈 | 管什么 | 怎么调 |
| --- | --- | --- |
| `yaw_sweep_accel_ff_gain` | **变速档专用惯量补偿**:同样是 `J×α`,但只在 `gimbal_active_profile=1` 时生效 | 在变速档单独调 |
| `yaw_unbalance_ff_amp` / `yaw_unbalance_ff_phase` | **变速档一圈一次的阻力**(偏重/线束):按转角正弦补偿 | 从 PID 输出的一圈一次波纹幅值起步,再标定相位 |

> 当前实现:**匀速档只使用方向静摩擦前馈,不使用周期或加速度前馈**。变速档使用
> `yaw_sweep_accel_ff_gain` 和一圈一次的 `yaw_unbalance_ff_*`。

> 那个正弦补偿不会"漂":6020 的单圈角度是绝对的,每次上电 `total_angle` 都从同一个点开始,
> 只要电机和云台之间没拆过,调好的相位就一直有效。
>
> 变速档使用 LD 设置 `0~10rad/s²` 的正向加速度,执行 `0→+7→0→+7rad/s` 的三角波。
> 目标到0时保持速度闭环和电机使能,不卸电。

### 前馈的启动斜坡(起步"抖一下"怎么治)

**症状**:刚进定速/变速档的那一瞬间云台会抖一下(有时还能听到"咯"的一声),之后就正常了。

**原因**:变速档前馈是直接加到电流指令上的。刚使能的那几拍,前馈项会**从0一下子跳到非零值**:

- 加速度前馈:进档第一拍设定值从0开始爬,`accel` 立刻就是 `YAW_SPEED_SLEW`(1200°/s²),乘上增益就是一笔电流指令;
- 一圈一次补偿:它只看角度,进档那一拍直接等于 `幅值×sin(当前角度)`,和上一拍(急停时是0)之间就是一个阶跃。

于是电流指令上多了一个台阶 —— 这就是那一下抖动。**这跟 Kp/Ki 调得对不对没关系,是结构问题。**

**办法**:让前馈乘一个从 0 爬到 1 的系数 `yaw_ff_ramp`,爬的速率是 `yaw_ff_ramp_rate`(初值 `YAW_FF_RAMP_RATE` = 5/s,即
0.2s 从0爬到满)。急停(`YAW_ZERO_FORCE`)会把系数清0,所以每次从急停起来都会重新爬一遍。

稳态时系数恒为1,前馈**全额**输出 —— 也就是说斜坡只在起步那一下起作用,上面两个前馈的调法、调好后的效果都不受影响。
嫌起步还是冲就把速率调小(0.2s → 0.5s 就把速率改成2);嫌前馈"迟到"导致起步那一下软,就调大;给0 = 关掉斜坡(和以前一样直接给)。

> 判据:盯着 `gimbal_yaw_pid_out`(速度环输出)和 `yaw_current_ff`(实际前馈),
> 两者相加才是最终电流指令。起步时如果 `yaw_current_ff` 是一条台阶,就是这个斜坡没起作用(速率给了0);
> 调好之后它应该是一条**斜坡**,而不是台阶。

### 为什么实测转速总比设定"慢半拍"(时间上的偏移)

变速档看波形时,最常问的就是这个:实测(红)在斜边上一直跟在设定(黄)后面一段,**看起来像是延迟了零点几秒**。
但它**不是延时**,而是"**转速差**":

- 设定要你**匀加速**(加速度 R,比如 300°/s²),匀加速需要一笔**恒定的电流**(要克服惯性和摩擦)。
- 速度环是"先有误差,才出力":纯 P 项要输出这笔恒定电流,就必须**一直保持一个恒定的误差**。
  于是实测就平行地吊在设定下面/上面 —— 在一条匀速爬升的斜线上,恒定的速度差看起来和"时间延迟"一模一样。

换算关系很直白,拿它就能量化你看到的偏移:

```
看起来的"时间偏移" = 斜边上的速度差 Δω ÷ 扫速变化率 R
速度差 Δω ≈ 那一拍需要的电流指令 ÷ Kp
```

比如斜边上红黄差 60°/s、R=300°/s²,那就是"看起来慢了 0.2s"。**所以这个偏移由环路增益(尤其 Kp)和有没有前馈决定,
和采样/滤波那几毫秒没关系**(1kHz任务+CAN反馈+反馈滤波加起来也就 3~5ms,折算成速度差才 1~2°/s)。

想让它小,按这个顺序:

1. **扫速专用前馈**:如果项目允许,给变速档单独做一个加速度前馈(独立增益),按实际惯量 `J` 标定。
   当前使用 `yaw_sweep_accel_ff_gain` 和 `yaw_sweep_decel_ff_gain`,只作用于变速档。
2. **加大 Kp**:偏移 ∝ 1/Kp。代价是毛刺/啸叫会变大,所以要在静音基线之上小幅试。
3. **平滑轨迹/降低扫速变化率**:三角波在峰值处加速度从 +R 直接跳到 -R,对电流是阶跃;改成
   S 曲线、正弦扫速,或在峰值短暂停留,都会显著减小幅值衰减和相位落后。`R` 小了,需要的电流也小。
4. **加大 Ki**:积分能慢慢把速度差吃掉,但慢(时间常数 ≈ Kp/Ki),而且给大了容易低频来回摆。

> 另外注意:你画的是 `sweep_speed`(变速档的目标),速度环真正拿到的是经过 `YAW_SPEED_SLEW` 限幅的
> `gimbal_yaw_speed_setpoint`。现在扫速 300°/s² 小于限幅 1200°/s²,两者重合;哪天扫速超过限幅,
> 设定本身就会被削,那又是另一回事了。

## 工作流程

`GimbalInit()`(实时系统启动前):

1. 注册yaw电机(CAN1 + `YAW_MOTOR_ID`)。`close_loop_type` 只打开速度环 —— 这台车全程只用速度环。
2. 上电默认`DJIMotorStop()`,即不给电流。
3. 订阅`gimbal_cmd`话题(由robot_cmd发布)。

`GimbalTask()`(1kHz):

1. `SubGetMessage()`取`gimbal_cmd`话题的消息;没有新消息时沿用上一次的指令。
2. 根据消息里的 `profile` 切换 **定速/变速两套速度环增益**。切到变速档时先把当前
   定速档的 `Kp/Ki` 保存到 `yaw_constant_kp/ki`,再使用 `yaw_sweep_kp/ki`;
   切回定速档时恢复。切换**不重置积分和输出**,避免换档电流突变。
3. 先刷新一遍调试变量(即使处于急停,也能从调试器看到电机反馈)。
4. 按 `mode` 分支:
   - `YAW_ZERO_FORCE`(急停):`DJIMotorStop()`置零电流,云台可以被手随便转(断电)。
     目标速度回0**不属于卸电**:电机继续保持使能,由速度环把实际速度压到0。
   - `YAW_SPEED_CTRL`(定速旋转、变速转动两个档走这里):把`target_speed`经过变化率限幅(`YAW_SPEED_SLEW`)后
     `DJIMotorSetRef()`,见上一节。
   - **没有命令就卸电**:`YAW_ZERO_FORCE` 分支除了断电流,还会 `PIDReset()` 清掉速度环积分
     (不清的话,下次进速度档会带着残留积分冲一下)。遥控器的 `A上D下`(以前的"停云台")现在也走这条,
     所以云台可以被手自由推动 —— 想恢复"通电刹住"的感觉,把 `robot_cmd.c` 里那一档改回 `YAW_SPEED_CTRL` 即可。

## 常改的参数(都在`robot_def.h`)

| 参数 | 作用 |
| --- | --- |

| `YAW_CONSTANT_FRICTION_FF_SLEW` | 静摩擦前馈接入/退出变化率 [电流指令/s] |

## 方向不对怎么办

把`robot_def.h`里的`YAW_MOTOR_REVERSE`改成1,**只改这一处**:

- 本车全程只用速度环。module 层的反向开关做的是"把设定值取反"(`dji_motor.c:381`),而速度环的反馈
  并没有跟着取反 —— 所以在这种纯速度环下改它的后果和以前(带角度环时)不一样,
  改完请**从小目标速度开始试**,确认不是反着跑或者发散。
- 提醒:反向这条路没有在实车上验证过,上电时请**从小目标速度开始试**。
